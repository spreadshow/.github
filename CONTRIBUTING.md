# Contributing to Spreadshow

Thanks for your interest in Spreadshow. This guide applies to every repository in the organization unless a repository defines its own.

## Ways to contribute

- **Report bugs** using the bug report template
- **Propose features** using the feature request template; explain the problem first, then the solution
- **Improve docs and examples**, which are often the fastest way to help
- **Write code**: connectors, core engine, UI

## Before you start

1. Search existing issues and discussions to avoid duplicates.
2. For anything larger than a small fix, open an issue first so we can agree on the approach.
3. Read the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development workflow

1. Fork the repository and create a branch from `main`: `feat/short-description` or `fix/short-description`.
2. Make focused changes. One pull request, one topic.
3. Add or update tests and docs for your change.
4. Run the linters and test suite locally before pushing.
5. Open a pull request and fill in the template.

## Commit messages

We follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`.

## Pull request review

- A maintainer reviews every pull request.
- Small, focused pull requests are reviewed faster.
- Please be patient and responsive to feedback; we try to do the same.

## Sign-off

By contributing, you agree that your contribution is licensed under the project's license. We use the [Developer Certificate of Origin](https://developercertificate.org/): add `Signed-off-by: Your Name <you@example.com>` to your commits with `git commit -s`.

## Questions

Open a discussion in the relevant repository.
